# Room Booking System API

RESTful API сервис для бронирования переговорных комнат.

## 🛠 Технологический стек
- **Java 17**
- **Spring Boot 3**
- **H2 Database** (In-Memory)
- **MapStruct** & **Lombok**
- **Jakarta Validation**

---


## 📌 Бизнес-правила и их обоснование

1. **Запрет пересечения бронирований:**
   - **Правило:** Нельзя забронировать комнату на интервал, который пересекается с существующим бронированием.
   - **Обоснование:** Исключает накладки и коллизии, когда две команды претендуют на одно помещение одновременно.

2. **Запрет бронирования прошедшего времени:**
   - **Правило:** Время начала бронирования (`startTime`) должно быть в будущем по отношению к моменту отправки запроса.
   - **Обоснование:** Защищает систему от ошибочных и невалидных исторических данных.

3. **Ограничение максимальной длительности (Максимум 4 часа):**
   - **Правило:** Длительность одного бронирования не может превышать **4 часов** (240 минут).
   - **Обоснование:** Предотвращает единоличное удержание ресурса одной командой на весь день и обеспечивает справедливый доступ к комнатам для всех сотрудников.

4. **Ограничение минимальной длительности (Минимум 30 минут):**
   - **Правило:** Длительность одного бронирования должна составлять не менее **30 минут**.
   - **Обоснование:** Исключает дробление расписания микро-слотами, снижает организационный шум.

5. **Ограничение горизонта планирования (Максимум 30 дней вперед):**
   - **Правило:** Нельзя создавать бронирование с датой начала дальше чем на **30 дней** от текущей даты.
   - **Обоснование:** Предотвращает неконтролируемое забивание календаря на месяцы вперед неактуальными встречами.

6. **Жизненный цикл и отмена:**
   - **Правило:** Бронирование создается в статусе `ACTIVE`. При вызове `DELETE /api/bookings/{id}` статус меняется на `CANCELLED`.
   - **Обоснование:** Сохраняет историю операций для аналитики, моментально освобождая слот для других сотрудников.

## 🚀 Запуск приложения

```bash
./mvnw spring-boot:run
```
Сервис будет доступен по адресу: `http://localhost:8080`

## 📋 Описание API (Эндпоинты)

### 1. Бронирования (`/api/bookings`)

#### `POST /api/bookings` — Создание бронирования
- **Request Body:**
```json
{
  "roomId": 1,
  "userId": 42,
  "startTime": "2026-10-01T10:00:00",
  "endTime": "2026-10-01T12:00:00"
}
```
#### `GET /api/bookings` — Список всех активных бронирований

#### `GET /api/bookings/archive` — Список всех бронирований включая отмененные

#### `DELETE /api/bookings/{id}` — Отмена бронирования (Soft Delete)

---

### 2. Комнаты (`/api/rooms`)

#### `GET /api/rooms` — Список всех комнат

#### `GET /api/rooms/{id}/availability` — Проверка доступности комнаты
- **Query параметры:** 
  - `from` *(ISO DateTime, e.g., `2026-10-01T10:00:00`)*
  - `to` *(ISO DateTime)*
